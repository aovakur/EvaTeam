\# Мониторинг дедлайнов задач (CMF / EvaTeam)



Скрипт для автоматического контроля сроков по портфелю проектов. Раз в день (или по расписанию) обходит все активные задачи, определяет просроченные, близкие к дедлайну и без срока, затем отправляет:



\- \*\*сводный отчёт руководству\*\* — агрегированные метрики и топ‑риски;

\- \*\*индивидуальные уведомления исполнителям\*\* — только по их задачам.



\---



\## Для кого



\- \*\*Руководители проектов и портфелей\*\* — получают сводную картину рисков без ручной выгрузки и фильтрации. Особенно полезно, когда нужно быстро показать статус портфеля и обосновать эскалацию (в том числе для публичного позиционирования как эксперта по управлению проектами).

\- \*\*Исполнители\*\* — получают точечные напоминания по своим задачам, без шума и чужих сроков.

\- \*\*Администраторы CMF / EvaTeam\*\* — могут развернуть скрипт как автоматический регламент и забыть про ручную рассылку.

\- \*\*Команда разработки и сопровождения\*\* — видят прозрачную логику приоритизации и контроля сроков, что упрощает ревью и поддержку кода.



\---



\## Что делает скрипт



1\. Запрашивает активные задачи (`in\_progress`, `open`) с фильтром по статусу.

2\. Для каждой задачи определяет эффективный дедлайн по гибридной логике:

&#x20;  - сначала `deadline` (обязательство);

&#x20;  - если `deadline` не задан — `op\_gantt\_task.sched\_finish\_date` (плановый срок из диаграммы Ганта).

3\. Сортирует по дате создания (`DESC`) — последние записи первыми.

4\. Классифицирует задачи:

&#x20;  - \*\*Просроченные\*\* — дедлайн раньше сегодняшней даты.

&#x20;  - \*\*Скоро дедлайн\*\* — осталось ≤ порогового количества дней (по умолчанию 1).

&#x20;  - \*\*Без срока\*\* — нет ни `deadline`, ни `sched\_finish\_date`.

5\. Формирует два типа рассылки:

&#x20;  - \*\*Руководству\*\* — единый отчёт: статистика + топ‑10 самых рискованных задач по каждой категории.

&#x20;  - \*\*Исполнителям\*\* — индивидуальные письма, сгруппированные по email, не более 50 задач в письме.



\---



\## Ключевые решения



\### Гибридная логика дедлайна



Не во всех задачах заполнен `deadline`. Скрипт не игнорирует такие задачи, а берёт плановый срок из Gantt — это повышает охват мониторинга и не теряет риски, которые есть только в плане.



\### Защита от перегрузки при большом портфеле



\- Выборка только нужных полей (`fields`) — не тянется вся модель задачи.

\- Пагинация по курсору (`created\_at < last\_date`) вместо `offset` — корректно работает с сортировкой.

\- Жёсткий лимит страниц (`MAX\_PAGES = 30`) — скрипт не уйдёт в бесконечный цикл.

\- Защита от дублей через `seen\_ids`.

\- Ограничение задач в письме (`MAX\_TASKS\_PER\_EMAIL = 50`) — письма не превращаются в «стену текста» и не попадают в спам.

\- Пауза между письмами (`PAUSE\_BETWEEN\_EMAILS\_SEC = 1`) — снижение риска блокировки почтового шлюза.



\### Два уровня отчётности



| Кому | Что приходит | Объём |

|------|-------------|-------|

| Руководство (`REPORT\_EMAILS`) | Сводный отчёт: метрики + топ‑риски | Кратко, до 10 задач на категорию |

| Исполнители (`responsible.email`) | Только свои задачи | Группировка по email, до 50 задач |
